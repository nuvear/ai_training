# M2 — Commerce

**Goal:** money moves correctly in every payment path.

## Scope
1. Models: order, order_item, payment, invoice, promo_code, seat_pool, refund (`DATA_MODEL.md` §4) with the stated check constraints.
2. B2C checkout: Stripe Checkout (cards, Konbini) in JPY and USD; promo application (one code max, all types from spec §4.3); 10% consumption tax on JPY; webhook handlers idempotent.
3. B2B: seat-pool purchase; invoice generation (sequential number, qualified-invoice field pulled from env `QUALIFIED_INVOICE_NO` — leave blank-safe), bilingual invoice PDF, `awaiting_transfer` → `paid` reconciliation flow.
4. Refund flow per spec §4.4 defaults; `refund.execute` tiered at ¥10,000 boundary.
5. Tools: `order.*`, `invoice.*`, `refund.execute`, `pricing.change`, `promo.create/deactivate/suggest`, `seatpool.create_offer` (`COPILOT_TOOLS.md` §3–§4).
6. Checkout screen matching mock (payment method trio incl. 請求書・銀行振込), receipts emailed bilingual.

## Exit criteria
- [ ] Stripe test-mode purchases succeed: card JPY, card USD, Konbini, and seat-pool via invoice path
- [ ] Promo math test-vectored (incl. HAYAWARI20 example: ¥45,000 −20% +10% tax = ¥39,600)
- [ ] Webhook replay does not double-fulfill (test)
- [ ] Refund above ¥10,000 requires owner tier (test)
